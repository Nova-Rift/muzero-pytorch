# Conditional replication package

The package integrates initializer83ef838 and readoutb02d760 on base4eb4003. Trainer14fece, source map, recipe, training seed73142017 and development/confirmation ranges are unchanged. Both templates retain null initialization hashes. No CUDA execution, selection, replication result or paid admission is represented by this package.

`replication_package.py --prerequisites PATH --output FRESH_PATH` stages pinned diagnostics, copied immutable prerequisites, a checked conditional graph, conservative runtime/storage estimates and unresolved gates. `package-manifest.json` binds every staged file, including the integrated initializer bytes expected by the readout. The relative `diagnostics/retention` and `diagnostics/paired` layout is retained so the unchanged raw audit helpers resolve correctly. Inputs are copied and never edited. The package contains no model checkpoints, runtime, site, credential, supervisor plan or executable job commands.

The graph is intentionally **not** workload-supervisor input: `executable:false`, `approved:false`, no `command` fields. Its exact topology is checked to reject dependency bypasses, seed/recipe changes and premature selection. A coordinator must derive and independently approve a concrete immutable supervisor plan after all unknown bindings are resolved. Review nodes must use explicit scientific-pass approval: an ordinary successful readout process does not mean `gate.passed:true`.

The critical chain is original development AND heldout arm selection → conditional admission → no-update frozen CUDA initialization → initialization evidence review → each lane's runtime/resume/collection gate → matched fresh2048 training → exact pair and recovery validation → six balanced development bouts → explicit development pass → four balanced confirmation bouts → confirmation readout. Each device job uses one device; parallel speedup is not assumed. Logical lanes do not request extra pods.
