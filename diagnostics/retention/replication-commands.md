# Conditional EGO command handoff

This is a source-only continuation of e6bebad. Production trainer14fece, initializer,
collection/recovery guards, evaluation and readout implementations are unchanged.
The EGO original development result passed; original heldout and coordinator
selection remain external prerequisites. MIR is not a fallback in these commands.
No paid action, CUDA run, model artifact or strength claim is included.

Generate with `python diagnostics/retention/replication_commands.py --output NEW_DIR`.
The output is a 27-node conditional command specification, **not** a supervisor
plan. Initial hashes, operational paths and all future receipt hashes are null.
`render(spec, job_id, bindings, reviewed)` returns argv lists only after every
ancestor has a receipt digest and all that command's bindings are concrete.
Those digests are transport bindings: the coordinator must independently inspect
receipt contents and authorize the next frontier. The renderer is not a scientific
review or budget/storage/lease admission system. Never feed the specification
straight to workload_supervisor or fill unknown hashes with invented values.

## Shortest admission sequence

1. Verify original EGO heldout PASS and select EGO; bind its actual readout and
   development evidence. Verify source publication, current seed collision audit,
   exact job storage and current quote/budget/lease/session limits.
2. Submit **only** `no-update-initialization`: one CUDA device, no trainer invocation,
   frozen Python3.12.3/Torch2.8.0+cu128, immutable trainer14fece, EGO null template.
   Preserve initial.npz, contract.json, initial-parity.json and initialization.json.
   The prefix equality is not the actual trainer-export gate.
3. Review those artifacts, bind resulting hashes and the accepted initialization
   review. Bind exact GPU UUID/runtime/site identity externally; GPU-name equality
   in current adapters alone is insufficient. Run each side's unchanged resume
   gate and reference collection. The references validate **actual trainer exports
   before first collect**, retaining full128 arrays with zero optimizer updates.
   EGO versus baseline collection equality is inapplicable; own reference parity
   remains mandatory. Candidate reference binds the paired receipt.
4. Submit each fresh2048 training command only after its receipts exist. The
   train_compressed wrapper retains960s encoder/850s trainer limits and600MB
   encoded limit per side. Actual initialization and own reference parity are
   checked again inside the real trainer before its first update. No warm start.
5. Recover both sides' four full-state milestones and other evidence. Run the
   two recovery commands then the exact-pair command in the listed order; mark
   their joint specification node done only after all succeed and are reviewed.
6. Run six development bouts, build hash-bound readout request from actual
   recovered artifacts, run readout and inspect `gate.passed`. False is terminal
   rejection. Only explicit PASS permits the four confirmation bouts/readout.
   No automatic model promotion.

For workload_supervisor convert only the currently admitted frontier to schema1
jobs: `command` is one rendered argv, `cwd` is an existing isolated per-loop work
folder, stage/resource reflect actual work, gpu_count1, max_parallel_loops1 for
serial execution, exact current lease/session deadlines. If retaining prior jobs,
keep their definitions immutable and make each same-loop job explicitly depend
on its predecessor. If beginning a new frontier, retain prior external completion
receipts in its admission manifest, not dangling supervisor dependency IDs. Split
three exact-pair commands into three chained jobs; do not join commands in shell.
Never manufacture runnable jobs for coordinator-only review nodes. Supervisor
success records execution; scientific-pass review remains separate.
